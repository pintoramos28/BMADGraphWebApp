High - `tests/e2e/shell-delivery.spec.ts`, `playwright.config.ts`: the new Playwright file starts a shared helper server in `beforeAll` on a fixed `4174` port while the suite is configured with `fullyParallel: true`. In Playwright, parallel workers rerun `beforeAll`/`afterAll`, so multiple workers can contend for the same port and later workers can kill the server another test is still using. `waitForServer()` also treats any `5xx` as “ready”, which can mask the contention into flaky passes/failures instead of surfacing it cleanly.

2. High - `scripts/shell-delivery-server.mjs`: the hosted delivery server reads its live bootstrap payloads from `src/test/fixtures/api/release-manifest.fixture.json` and `src/test/fixtures/api/support-matrix.fixture.json` at runtime. That works from a full repo checkout, but a real static-host deployment normally ships `dist/` plus thin server glue, not `src/test/**`. In that packaging model every `/api/release-manifest`, `/api/support-matrix`, and `/api/health` request will fail with `500`, so the delivery path is not actually self-contained.

3. Medium - `package.json`, `playwright.config.ts`, `docs/dev-environment.md`: the new `preview:shell` flow bypasses the repo’s existing runtime guard. There is a `prepreview` hook for `npm run preview`, but no corresponding `prepreview:shell`, and both the docs and Playwright now invoke `npm run preview:shell` directly. On machines where bare `npm` resolves to the wrong Node installation, this new hosted-shell path can run under an unsupported runtime instead of failing fast.
