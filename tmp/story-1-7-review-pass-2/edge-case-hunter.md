1. `[medium]` Hosted delivery drops slash-terminated shell routes instead of applying SPA fallback. In [scripts/shell-bootstrap-metadata.mjs](/home/pinto/repo/BMADGraphWebApp/scripts/shell-bootstrap-metadata.mjs:93) and [src/services/release/shell-bootstrap-metadata.ts](/home/pinto/repo/BMADGraphWebApp/src/services/release/shell-bootstrap-metadata.ts:83), `isShellRoutePathname()` accepts `/workspace` and single-segment `/workspace/:id` / `/review/:id`, but rejects `/workspace/`, `/workspace/demo/`, and `/review/demo/`. React Router matches those URLs, so direct requests to them will 404 at the thin server even though the client router would accept them. The e2e coverage in [tests/e2e/shell-delivery.spec.ts](/home/pinto/repo/BMADGraphWebApp/tests/e2e/shell-delivery.spec.ts:117) only exercises slashless forms.

2. `[medium]` The new bootstrap validation does not actually prove the payloads are schema-valid before health checks pass. In [scripts/shell-bootstrap-metadata.mjs](/home/pinto/repo/BMADGraphWebApp/scripts/shell-bootstrap-metadata.mjs:18) and [src/services/release/shell-bootstrap-metadata.ts](/home/pinto/repo/BMADGraphWebApp/src/services/release/shell-bootstrap-metadata.ts:16), `validateShellBootstrapMetadata()` only checks version/url/compatibility alignment. If either JSON loses some other required field, [vite.config.ts](/home/pinto/repo/BMADGraphWebApp/vite.config.ts:27) can still emit `/api/health = ok` and the preview server can still serve the bad assets, deferring the failure until the browser bootstrap path hits Zod. That leaves a delivery/setup blind spot; the helper tests in [src/services/release/shell-bootstrap-metadata.spec.ts](/home/pinto/repo/BMADGraphWebApp/src/services/release/shell-bootstrap-metadata.spec.ts:31) only cover drift, not malformed shape.

3. `[low]` Malformed percent-encoded paths currently surface as `500` instead of a bad-request/not-found result. In [scripts/shell-delivery-server.mjs](/home/pinto/repo/BMADGraphWebApp/scripts/shell-delivery-server.mjs:84), `decodeURIComponent(urlPathname)` can throw on inputs like `/%E0%A4%A`; that exception is caught by the top-level handler and returned as a generic server failure. This is a boundary-path handling gap in the new server, and there is no scoped e2e covering malformed path input.
